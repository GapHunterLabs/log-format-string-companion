Reports a log call whose message placeholders do not match the number of arguments: SLF4J-style {} in Java and Kotlin (log.info("User {} logged in from {}", userId, ip)), and %-style specifiers (%s, %d, ...) in Python logging.

The mismatch only shows at runtime: a leftover placeholder is printed literally, or an extra argument is silently dropped. A trailing exception argument in SLF4J is not counted as a placeholder argument.
